## Follow-up: newly materialized entity boundary

The former phrase "first materialized during the final C25 pending flush" was too broad. The `finally` block of `BattleLateEntityLifecycleModule.Run` calls `SimulationWorld.FlushLateEntityPendingMutationsForModule`, whose body only flushes pending unregister and destroy queues; it does not materialize an OPoint. Actual C25 OPoint task materialization occurs in the per-slot `FlushQueuedObjectPointTasks` calls. The normal `SerialTickAll` that follows uses `SimulationEntityTraversal.Enumerator.MoveNext`, which reads each current runtime slot rather than a pre-C25 snapshot. Therefore a child still active after C25 can enter that later scan, including a child allocated into a slot that C25 already passed.

For such a child, `SerialTickAll(tick, true, true)` skips `SimTransit` and `SimTU`. Base `LF2Entity.RunPostNativePhysicsSerialForWorldPass` is empty; the `LF2SpecialAttack` override requires a matching `nativePhysicsCompletedTickForSerial` and a type-3 state change before its `StateEntryEvent` path. The current type-3 `state_entry` dispatch has no gameplay writer, as established above. The scan still invokes `RefreshRuntimeSnapshotAfterFrameAdvance` for non-exact-character types. Source inspection alone does not establish every possible wrapper/runtime field value for a newly materialized child or every pooled-object history. Thus this narrows the only conditional boundary to a same-initial-state child snapshot/visible-result first difference; it does not justify changing the tail or running a broad matrix.
