Status: `READ_ONLY_COUPLING_CONFIRMED / IMPLEMENTATION_PENDING` (2026-09-22). This note refines the transition audit; no script or asset was edited for it.

The alignment table §1.2 and rows P-19/G-08 exclude full native result-page/KO/scoreboard and full native selection UI. Unity's own result and selection visuals may remain. The exclusions do **not** cover native living-group eligibility, timer80 end signal, timer101 logical result record, held continue at >=144, timer350 transition command, combat-world freeze or the battle-to-next-state request. A visual page appearing before native timer101 is not by itself a required visual fix; letting its state change combat input or entities is still a logic defect.

Current Unity `BattleResultsOutcomeHostWriter.UpdateSummaryActivation` sets the old two-side `IsActive` page at `BattleEndPhase>=11`. `NTSDBattleTickSystem.RunTick` reads `Results.IsActive` before its combat passes: when true it skips `PollHumanInput`, changes the CharacterInput gate, and prevents `NeedClearInput` from being consumed. The formal `GameSession28::step` continues to pass configured slot input to `SimulationTickDriver28::step` on result-visible ticks until transition350; the isolated formal complete-session fixture has nonnull `last_tick` at349 and null at350. Thus the old visual page currently owns combat input policy too early. `BattleResultsSceneHostTickAlignmentEditorTests.ResultsActiveTickRunsFullWorldTailWithoutEntityHumanPoll` explicitly asserts the old null-human-poll behavior. That assertion is a historical Results-UI seam, not evidence that it matches the current Logan playable battle rule; it needs a source-corrected oracle when the core route is fixed, while its P1/P2 pressed-edge page-input tests can remain visual/UI regressions.

After activation, `BattleResultsWriter.RunActiveTick` receives P1/P2 pressed edges after the world tick. Its summary/settings flow edits result tables and, through `RunSettingsPhase`, may set `PendingHostAction`, call `SyncReserveOwner`, change `FallDamageDiv` on active characters, modify Match difficulty/stage selection, or queue UI sounds. The global search found `PendingHostAction` writes, serialization and tests but no production reader. These are current-state code observations, not a verdict that every UI setting is prohibited. A transition integration must assign any next-match configuration write to a host-owned next-match transaction and prohibit modification of the frozen old combat world after native350. The mode4 reserve path must stay explicitly inventoried until its formal authority question is resolved; the P-19 exception alone does not authorize deleting it.
