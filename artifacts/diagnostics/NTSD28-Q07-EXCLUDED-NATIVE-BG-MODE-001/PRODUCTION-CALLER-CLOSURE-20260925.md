A source search under `Assets/NTSD/Scripts` found no background DAT read literal or parser call in production.

That explicit/no-snapshot path calls `LoganModeComboInput.Capture(source)`, which reads native `data/mode.dat` and a selected child if present, or returns null when the parent DAT is absent. Current in-repository calls without a snapshot are in Editor tests and `NTSD28UnityRawCaptureEditor` diagnostics, not the selected configured production prewarm. This is a retained historical/diagnostic capability and a public-API future-caller risk; this static census does not prove that an external assembly or reflective caller cannot invoke it. It is not justification to reintroduce the two excluded DATs or to remove the diagnostic parser without an owned change.
