2026-09-25 input-schema clarification before the new Play result: formal `InputKey28`/`input_routing.cpp` assigns bits 0..6 to depth-up, depth-down, left, right, attack, jump, defend (the DDJ held masks are therefore 64, 2, 32). The Unity diagnostic's new `proxyCurrent`/`proxyPrevious` arrays and bitsets are explicitly **raw `NTSD28InputProxyBlock` indices**, not a decoded formal input mask. `NTSD28InputTwoPassModule.FreezeProducerState` copies runtime `KeyJump`, `KeyDefend`, `KeyAttack` to current indices 4, 5, 6, whereas `NTSD28NativeComboStateMachine` labels those canonical indices Attack, Jump, Defend and projects them back to legacy fields in a different order. `NTSD28NativeInputPreprocessor` can additionally remap current indices before native combo processing. Thus neither a raw bitset nor a queued physical L/S/K row may be compared numerically with a formal `InputButtons28` mask without proving the exact producer, remap state and capture point for that row. The new diagnostic also records raw edge-window bytes separately; those are countdown state, not held-key bits. This is a static schema boundary, not an observed Unity/EXE input mismatch.
