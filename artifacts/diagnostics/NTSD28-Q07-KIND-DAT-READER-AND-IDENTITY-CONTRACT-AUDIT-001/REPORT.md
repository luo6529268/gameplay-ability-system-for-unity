## Actual native behavior and Unity owners

1. `GameSession28` selects the `kind.dat` global DAT. Missing file selects the identity-attested parsed one-record fallback; a selected but invalid file aborts session initialization. It supplies the catalog to World step options. `KindCatalog28::parse_text` trims whitespace, strips `;` and `#` comments, requires strict integers and exact list counts, limits records to 100, retains warning diagnostics for unknown content, and finds the first record with a matching effect. These are the parser and selection rules to preserve, including the distinction between missing and malformed input.
2. `HitCandidateBuilder28::append_pair_geometry` applies `classify_kind_table_candidate` before ordinary kind/effect/type gates and rectangle projection. It rejects a target only when its **type is 3**, its OID matches a record effect, the attacker OID appears in that record's respond list, and ITR kind is not 9. Unity `BruteForceSceneQuery.IsBlockedReleaseOidInteraction(attackerOid,targetOid,kind)` hardcodes the one-record OIDs but has no target-type argument. This is a confirmed source-contract difference. Formal `catalog.csv` has 330 object entries and no object ID 209, so a default-roster observable difference is not yet demonstrated; it must be tested using a controlled type-3/type-0 OID209 pair without claiming a natural roster case.
3. In the type-3 hit continuation, `BattleWorld28` scans the active catalog in order for a bound attacker and respond target, then transfers group, owner, definition and OID and selects record.frame (zero falls back to 40). Unity `BattleDamageWriter.IsNativeLockedKindTransformCandidate`, `ApplyNativeLockedKindTransform` and `IsKarasuOid` hardcode the one-record values and frame 40. `BattleEcsHitExecutionPlan` has additional calls to this candidate helper, so the new catalog must reach both the ordinary and ECS paths; changing only one helper is insufficient.
4. Unity `LoganObjectCatalog` captures object definitions, fusion input and mode input into `LoganContentIdentity`. `LoganVisualContentCandidate.AssertInputsCurrent` checks fusion, mode, object definitions and images. Neither selected `kind.dat` bytes nor parsed semantics currently join the source cache key, content identity, freshness check or prepared World data. `BattleRuntimeDataCatalog` and the current lockstep identity use `CatalogFingerprint`; a new kind component can change session fingerprints and existing fixed-fingerprint fixtures. Version and replay compatibility belong to R15 and must be handled explicitly.
