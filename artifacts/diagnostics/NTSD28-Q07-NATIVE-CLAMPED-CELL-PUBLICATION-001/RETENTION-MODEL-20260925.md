# Formal clamped-cell queued-array retention model

Read-only source-data scan of all formal `resources/runtime/decoded_dat/**/*.dat` BMP-section sheet declarations against the matching formal VFS PNG dimensions. It uses the native horizontal `row`, vertical `col`, one-pixel separators and authored full cell size, and counts each declared cell whose source rectangle crosses an image edge. The scan found 31 affected sheet lines, 1,212 cells and 48,533,904 raw RGBA bytes (46.286 MiB); all referenced PNG paths existed. This reproduces the earlier 1,212-cell census. Four largest affected sheets alone total 13,313,364 bytes (12.697 MiB); the largest one is `c/rai/a/rai1.png` at 49 cells × 159×159 RGBA = 4.726 MiB. The largest single cell in this corpus is 199×604 RGBA = 480,784 bytes.

`CharacterAnimtorManager.ProcessAndCreateSpritesForCandidateAsync` currently stores each cell `Color32[]` in `clampedCells` before `cpuSemaphore.Release()` and then awaits `uploadSemaphore`. The release allows more than four completed CPU tasks to queue for upload with their arrays still referenced. Thus the 46.286 MiB is a possible **retained payload across the queue**, not an observed process high-water and not the full memory cost: decoded/processed sheets, hash byte buffers, 36 unique textures, virtual atlas pixels and atlas pages are additional. The proposed correction retains only content hashes across this await and reconstructs pixels at the first unique upload, without changing the sampled bytes or atlas order. A separate original-Editor runtime capture is still needed for actual high-water.
