Status: read-only design audit on 2026-09-27; no production implementation or exit claim. This is a continuation of the master alignment document's Q10/O-02 row, not a separate rule authority.

The formal battle path is `GameSession28::step` -> `NativeStageCamera28::step(world, background.width)` -> `main.cpp` uses `locked_local_battle_stereo_layout28(session.camera_x())` after each successful tick -> `audio_backend.cpp` computes a piecewise integer matrix from `event.world_x - camera_x` -> mono XAudio2 source voice `SetOutputMatrix(1,2)`. The controlled source diagnostic yielded `003` rule X649/camera0/53:47 and `004` rule X729/camera0/41:59. The 1330 width in the controlled formal stage23 trace is evidence for that trace only; the original background DAT is excluded from Unity content and must not be imported to manufacture camera parity.

The Unity call chain is `LF2Entity.QueueBattleSound` -> `SimulationWorld.QueueSound` -> `PendingSoundEvent.WorldX` -> `NTSDSoundPlayer.PresentSound` -> `PlaySfx` -> `PlayPreparedCue`. The main entity wrapper queues `GetRuntimeXInt()` (D-024 physical X). Two direct LF2Entity sites, one LF2SpecialAttack site, NTSDBattleTickSystem hit victim, and fixed-X BattleResultsWriter sites also call `QueueSound` directly. The selected natural Naruto cues therefore arrive as physical X664/787 while their source-rule X is 649/729; the fallback mono voice sets `spatialBlend=0`, `panStereo=0`. `PendingSoundEvent.WorldX` also enters parity snapshot and lockstep checksum, so silently changing its domain would alter the state contract and requires declared snapshot/checksum tests.

The v3 AudioRenderer run proves a battle-only mono voice can approximate a target XAudio2 matrix using `pan=(R²-L²)/(R²+L²)` and `gain=sqrt(R²+L²)` in this Unity 2022.3 stereo output. This law is measured with one temporary 440 Hz mono clip. It says nothing yet about stereo-clip matrix behavior, mixer effects, selected battle cue output or root EXE speaker capture. `PlayPreparedCue` also adds AudioItem random volume/pitch, wall-time throttling, 3D range and pool reuse; the production Task must audit how these interact with the formal per-event matrix and whether nonbattle `PlaySfx` shares the same function.
