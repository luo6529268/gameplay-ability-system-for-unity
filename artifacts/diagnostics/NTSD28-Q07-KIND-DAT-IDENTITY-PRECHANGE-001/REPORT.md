# Q07 kind.dat identity and World publication pre-change audit

Observed 2026-09-23 in the original Unity project. The staged formal `kind.dat` and native parser/selection foundation are already verified separately (24/24 focused tests); combat consumers still use locked values.

`LoganObjectCatalog` currently captures object definition, fusion and optional mode; its `ContentIdentity` is five-component V2 when mode exists. `LoganVisualContentCandidate.AssertInputsCurrent` checks mode/fusion/object/image/words and Q09 kill icons, but not kind. `BattleRuntimeDataCatalog.Prepare` checks only object/fusion identity and then freezes the fusion table plus identity; it has no kind lookup. `SimulationTickDriver.BeginBattleAllocationSeal` passes the published catalog into that Prepare before the capacity seal. These are the minimal publication seam and lifetime.

R15 coupling is concrete: `NTSD28TraceContentIdentity` recognizes only V1/V2 and emits no kind components; `Tools/NTSD28Parity/TraceContentIdentity.cs` validates only those property sets. The native source-model emits V2; it must remain V2 until a separate native V3 capture package. Several Editor tests hardcode the current formal V2 raw/semantic/projection values, so their historical vectors must be separated from new current expectations. Extending production identity without this version boundary would make trace validation misleading or fail at header parsing.

Decision for the next bounded code package: the formal mode-present path uses seven SHA-256 component bytes in order object, fusion raw, fusion semantic, mode raw, mode semantic, kind raw, kind semantic under `NTSD28_LOGAN_BATTLE_INPUTS_V3`. A no-mode fixture is valid: `LoganModeComboInput.Capture` returns null for missing mode, while kind still affects battle behavior. It therefore uses distinct `NTSD28_LOGAN_BATTLE_INPUTS_V3_KIND_ONLY` over object/fusion/kind; no fabricated mode hash. Keep previous V1/V2 APIs/vectors for history. Decoder tag stays `NTSD28_LOGAN_DAT_SEMANTICS_V3` because the versioned input tag changes the composite raw hash. Selected file and locked fallback may have the same parsed semantics while retaining different raw input identities. Publish the immutable selected table only after complete identity verification; no combat consumer change in this package.

Evidence limits: static caller/field audit only. No new code, test, Play Mode or formal EXE comparison was run for the planned V3 package. Q07/R15 remain open. The unrelated current Q09 edits in the visual candidate and manager must be preserved.
