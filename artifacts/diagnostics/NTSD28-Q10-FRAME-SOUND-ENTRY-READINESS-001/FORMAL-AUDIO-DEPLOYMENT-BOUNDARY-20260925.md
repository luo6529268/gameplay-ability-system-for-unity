Status: `READ_ONLY_CONTENT_AND_CALLER_AUDIT / ROUTE_UNDECIDED / NO_AUDIO_COPY`.

The original Editor direct-Battle `Editor.log` contains 905 failed prewarm warnings for 903 distinct normalized WAV paths. All 903 resolve under the formal NTSD 2.8-Logan `resources/runtime/vfs`, totaling **31,891,393 bytes (30.41 MiB)**; none is present at the same path in staged `Assets/NTSD/Content/LoganRuntime/vfs`. The formal VFS has **981 WAV files, 33,571,573 bytes (32.02 MiB)**. The difference between the 903 demanded paths and all 981 formal WAVs is 78 files, but the current audit has not proved that all 78 are unused in other battle entry paths. This count is the direct Editor prewarm demand, not 903 audible events or a complete audio content decision.

`NTSDSoundPlayer.GetOrPrepareCue` currently builds every fallback path under `Application.dataPath/NTSD/Sound` (`NTSDSoundPlayer.cs:214-260`). `PrepareBattleCuesAsync` collects character-manager cue IDs plus 13 built-in IDs and seals the catalog after attempted prewarm (`:100-137`). `LoadPreparedClipsAsync` asks `NTSD_ResourceLoader.LoadSingleAudioClipAsync` for a file-path cue, and the current Battle Scene `AudioController.AudioList` is empty. Thus merely staging WAVs under `LoganRuntime/vfs` would leave the current sound player reading its old `Sound` tree. A bounded battle-only source selection and Player packaging contract is needed in addition to any resource deployment. The 71 same-path old `Sound` WAVs are not content-equivalent to formal WAVs (0 whole-file SHA matches; 43 PCM payloads differ), as measured in `REPORT.md` and its CSV evidence; fallback to them cannot be called formal audio parity.

The separate formal BGM table `decoded_dat/data/bgm.dat` names eight WMA files. The formal VFS contains exactly **8 WMA files, 4,529,950 bytes (4.32 MiB)**; staged VFS has none. `GameSession28` consumes the table in a post-roster music-selection flow that can carry into battle. The current Unity `NTSD_ResourceLoader.GetAudioType` accepts WAV, OGG and MP3 only (`NTSDResourceLoader.cs:613-641`), so simply staging the formal WMA bytes would not make this loader play them. No project NTSD script currently references `bgm.dat` or a BGM table. This BGM path crosses the preserved Menu/selection boundary; it requires its own declared owner and exact entry/exit behavior, not an unreviewed change to ordinary Menu audio.

Q10 implementation decision still required: choose a packaged formal battle-audio root (or an explicitly supported external source with a Player sidecar contract), decide whether to deploy the full 981 WAV set or a measured closure that also covers non-prewarm events, route only formal battle cue paths through it while preserving project UI/audio exceptions, and separately define how the eight WMA BGM tracks are made playable and selected without changing nonbattle behavior.
