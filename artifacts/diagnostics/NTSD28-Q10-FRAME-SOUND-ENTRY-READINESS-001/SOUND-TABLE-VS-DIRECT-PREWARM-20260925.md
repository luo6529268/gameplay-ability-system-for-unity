# Q10 sound-table paths versus direct-Battle prewarm (2026-09-25)

Status: `READ_ONLY_SCOPE_REFINEMENT / NO_AUDIO_COPY / NO_SCRIPT_EDIT`.

The current formal/staged `decoded_dat/data/sound.dat` contains 18 ordered `file:` paths. The original Editor's current `Editor.log` contains 903 distinct normalized paths from `NTSDSoundPlayer`'s direct-Battle failed-prewarm warnings. A read-only parse opened that live log with `FileShare.ReadWrite`, selected only the exact warning prefix `Battle cue prewarm failed and was sealed without a streamed clip:`, normalized backslashes to slashes, and intersected the path set with the 18 DAT entries. The first ordinary `File.ReadLines` attempt failed because the Editor held the log open; its empty result was discarded, and the successful shared-read result below supersedes it.

Only **4/18** sound-table paths occur in the 903-path prewarm set: `data/001.wav`, `data/006.wav`, `data/032.wav`, and `data/033.wav`. The other **14/18** are `data/002.wav`, `data/010.wav`, `data/011.wav`, `data/004.wav`, `data/016.wav`, `data/017.wav`, `data/020.wav`, `data/021.wav`, `data/025.wav`, `data/039.wav`, `data/065.wav`, `data/066.wav`, `data/068.wav`, and `data/085.wav`. All 18 exist in formal `resources/runtime/vfs`, totaling 231,782 bytes; the four overlapping files total 50,528 bytes and the 14 nonoverlapping files total 181,254 bytes. The current staged VFS still has no same-path WAVs.

Combining the previously measured direct-prewarm set (903 paths, 31,891,393 bytes) with these 14 additional paths gives a **917-path, 32,072,647-byte lower bound** for those two known entry sources. The formal VFS has 981 WAVs, so 64 files and 1,498,926 bytes remain outside this two-source union; their other battle/selection reachability has not been decided. These are distinct-path byte sums, not a proposed final deployment list.

This proves the direct-Battle prewarm demand is **not a complete closure** even for the already-staged native sound table: deploying just those 903 paths would omit 14 table entries. Conversely, deploying the 18 table entries would leave most of the 903 character/frame prewarm demand unfilled. The searched Unity NTSD scripts do not reference the literal `sound.dat`, whereas native playable `audio_backend.cpp` loads it and `game_session.cpp` contains indexed consumers; this is a source-level route difference, not an audible Play comparison. The live log can rotate or grow, so the counts describe this read at this date; the 18 DAT entry list and formal byte sizes are stable source-file observations.

Q10's later deployment contract must account for both path sets and their event consumers before it can claim battle-audio content coverage. This audit does not authorize bulk WAV copying, WMA/BGM changes, Menu audio changes, or a claim that any cue was heard. It leaves Q07's DAT byte staging and Q10's playback/runtime gates open.
