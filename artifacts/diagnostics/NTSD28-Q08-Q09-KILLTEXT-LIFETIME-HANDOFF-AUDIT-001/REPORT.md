# Q08/Q09 `#killtext` lifetime handoff audit

Date: 2026-09-22. Status: `STATIC_FIRST_DIFFERENCE_CONFIRMED`. Read-only audit; no Unity Editor test, Play or formal-EXE pixel result.

The formal playable `GameSession28::initialize_resources` first selects the mode child named by `data/mode.dat` and calls `load_native_knockout_feed_config28` on that child. The loader reads the child's `<bmp_begin>` record: `bound` controls display enablement, while `times` independently supplies `lifetime_ticks`. It also reads layout, mode/id filters, type-image paths and sounds. The current selected `data/mode/ntsd.dat` has `#killtext bound:1` and `times:70`, with modes 0/1/4 and three referenced icon PNGs. These exact DAT and icon bytes are already staged in the original Unity project.

In formal `GameSession28::step`, the post-core audio loop and `prune_native_knockout_tail(world.sequence(), lifetime_ticks)` execute **if and only if a knockout-feed config was loaded**. The branch does not additionally check `bound` or the current allowed-mode list; a loaded but visually disabled record can still cause expiry. If the config is absent, this Session does not prune. Negative lifetime is a native no-op in `BattleWorld28::prune_native_knockout_tail`. The render snapshot's 30-tick visible window is separate from `times` and must not be used as the record expiry.

Current Unity `NTSDBattleTickSystem.RunPresentationAndCleanupPhase` always calls `world.PruneNativeKnockoutTail(tickIndex, 70)` after `BattleResultsFlow`. That matches the captured selected `times` only while this exact feed config is present; it differs from a missing or changed mode child. `LoganModeComboInput` already captures the first mode child and both DAT-byte fingerprints and `SimulationTickDriver.ApplyPublishedModeComboBeforeFirstTick` consumes the published catalog before tick 0. These are useful existing ownership seams, but its combo tuple does not parse or publish `#killtext`.

Next bounded implementation must capture the selected child's knockout-feed record with the same content identity/freshness boundary as the published mode input, preserve config absence distinctly from `bound=0`, and publish at least the optional lifetime to the match-owned World before the first tick. Snapshot/restore/checksum must include any runtime value that changes expiry. Q09 owns the full feed config, icons, layout and draw commands; Q08's expiry handoff should consume that published config. A change needs its own pre-edit Task Contract and Change Record. Do not merely replace the literal `70` with another unversioned constant, and do not prune a missing config.
