# Q07 old-content Menu fallback boundary (2026-09-26)

Status: `SELECTED_FORMAL_BATTLE_ROOT_VERIFIED / LEGACY_MENU_FALLBACK_RETAINED / OLD_FILE_DELETE_GATE_OPEN`. This is a read-only owner decision aid, not an authorization to remove old content or change Menu behavior.

The current serialized `GameConfig.asset` selects the nonempty `Assets/NTSD/Content/LoganRuntime` root. In that condition `LoadingPrewarmController.PrewarmOnceCoreAsync` invokes `CharacterAnimtorManager.PrewarmConfiguredLoganContentAsync`; the original Editor's Menu→Battle formal-root callback Play has reached `BattleRunning` with a formal publication, while the separate empty-root callback Play rejected Battle entry before a live World. The earlier exact requests and their SHA are in `NTSD28-Q07-OLD-ASSET-REFERENCE-REFRESH-001/CURRENT-LEGACY-READER-REACHABILITY-20260925.md`. These results distinguish the selected production branch from the still-reachable empty-root branch.

When the root is empty, `LoadingPrewarmController` queues `CreateCharacterConfigTask` and `CreateCharacterSpriteTask`, then validates the legacy publication. Its `Start` waits for `IsPrewarmed` and drains `pendingTexts` before calling `MenuUIController.ShowSelectGameMode()`. The existing empty-root Play probe follows that menu flow through character/mode selection and only then checks Battle rejection. Replacing the empty-root branch with an immediate error would change this Menu/loading flow; merely deleting its old DAT/images would cause that branch to fail before the existing Battle-entry guard. Neither is a battle-only no-op.

Current bounded disposition: keep the default nonempty formal-root Battle path, its fail-closed Battle-entry guard, and the historical empty-root Menu/Editor inputs separate. Do not delete or move the 138 old indexed DAT or 383 old indexed character images, and do not rewrite `LoadingPrewarmController`, `CharacterAnimtorManager.RefreshAllData`, the Editor preview or the public default reader as part of a battle-only cleanup. The 521-row current retirement inventory remains `deleteAuthorized=false`. A future explicit change to the compatibility/authoring surface needs its own user-visible scope and Menu behavior acceptance; selected formal Battle tests alone cannot certify that change.

This conclusion does **not** say old content is selected in the current formal battle, nor does it close Q07. Q07 still needs natural content/visual coverage and final acceptance. It only prevents the old-file count from being treated as a safe bulk-delete list or an automatic reason to alter protected nonbattle UI.
