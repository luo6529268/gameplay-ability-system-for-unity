## Current Unity paths and first visible gap

The world stage module calls `BattleCentralRenderSystem.FlushLatestPublishedFrame`, then runs `LateRendererUpdateAll` unless CentralOnly bypasses legacy shells. `RenderAlpha` is computed by the driver but is not passed to either presentation path. There is no battle-owned render-FPS setting or `Application.targetFrameRate` writer in `Assets/NTSD/Scripts`; unrelated MoreMountains tooling can alter the global frame rate, and project quality tiers have different `vSyncCount` values. Thus neither `RenderAlpha` alone nor a single observed frame duration identifies the native `render_fps > 30` policy. `BattleDynamicMeshBackend.Build` writes immutable `BattleRenderCommand.Position` into mesh vertices. The renderer must apply accepted deltas during a new display build or an equally lease-safe presentation-only upload; it must never modify the published logic frame or runtime positions. Current commands have `Shadow`, `Entity`, `OverlayGlyph`, `HitRecord`, and `BleedMark`. Formal interpolation moves entity body by X and Y+Z, shadow by X and Z, bleed by X and Y+Z, and selected lives/nameplate/combo overlays by their formal rules; it does **not** move hit sparks. Unity currently collapses several entity-attached labels into `OverlayGlyph`, so command metadata must distinguish the exact anchor rule instead of moving every glyph as a body or guessing from sort order. The separate foot-marker and overhead-health meshes read stable anchors from the same entity command; their visible anchors must follow the accepted display delta without rewriting logic HUD/health state.
