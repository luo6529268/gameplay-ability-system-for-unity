# 文件删除、移动与覆盖审计合同

标识：`FILE-REMOVAL-AUDIT-001`。来源：用户2026-10-01要求以后所有删除处理都做记录，避免再次找不到原因。长期入口为 [AGENTS.md 第13.3节](../../AGENTS.md)，统一登记在 [FILE-OPERATIONS/INDEX.md](FILE-OPERATIONS/INDEX.md)。

## 范围与授权

本合同适用于本任务和受委派代理对项目文件进行的删除、清理、移动或隔离、替换、覆盖，以及会丢弃内容的Git操作；包括已跟踪、未跟踪、忽略文件、资源、文档、测试输出及临时文件。通过Unity API、导入器或脚本间接安排这些操作，同样需要记录。战斗实体的内存回收不属于文件操作。

记录不能代替用户授权。已有精确授权直接引用，不重复询问；授权未覆盖的路径不能追加。工具拒绝后保留拒绝记录，不换shell、解释器或工具绕过。记录和备份不得位于操作范围内。

这份合同保证遵守合同的任务操作可追溯，不能保证用户、其它程序或未受约束的进程自动留下记录。外部缺失仍需进程/系统审计证据才能归因；缺证时明确记为未知。

## 执行前

1. 建立唯一Operation ID，并在索引登记 `PLANNED`。写明Task/Change ID（适用时）、原因、用户授权原文或准确会话来源、执行代理/任务、工作目录和预期结果。
2. 保存逐文件manifest：解析后的绝对路径、相对路径、类型、字节数、SHA-256、Git跟踪/暂存/工作区状态；Unity资源包括对应 `.meta`、GUID和引用影响。递归操作先展开全部路径，核对解析路径仍在批准根目录内；符号链接/重解析点不能未经核对递归跨出范围。
3. 保存现有未提交差异、未跟踪内容及可能被覆盖的文件到范围外备份，并核对备份哈希。干净的已跟踪文件可登记准确Git commit/blob及恢复步骤；HEAD不能替代未提交内容备份。恢复来源无法核实时不执行。
4. 保存拟执行的完整命令或API/脚本入口及参数，核对通配符和目录的实际展开结果；“资源清理”“旧文件”等概括不能代替精确范围。
5. 记录开始时间（ISO 8601含时区，建议同时记UTC），执行前落盘。先记录再操作，不能事后凭记忆补清单。

## 执行后

立即追加实际命令/API、执行任务和进程标识（能取得时）、开始/结束时间、退出码或异常、stdout/stderr文件位置及实际触及路径。外部工具还需记可观察的实例/项目标识；命令提交成功不等于操作完成。

逐文件核对操作后状态、目的地和哈希，对照操作前manifest，检查范围外变化。移动证明原处缺失及目的地完整；覆盖保留原内容恢复来源与新内容身份。记录实际成功、失败和未执行项。

状态使用 `PLANNED / RUNNING / VERIFIED / FAILED / PARTIAL / REJECTED / CANCELLED / RESTORED / UNKNOWN_CAUSE`，只按证据推进。拒绝记录包含原始错误和进程是否启动；部分执行保存已执行清单，不盲目重跑。完成后回链对应Task/Change/交接。

## 未计划缺失与恢复

发现缺失先暂停针对受影响文件的写入，保存Git状态、缺失清单、仍存文件哈希、日志和时间证据，在索引登记 `UNKNOWN_CAUSE`。日志只证明观察到缺失时，不能据此认定该程序发起删除。

恢复作为新的有记录操作，引用原事件、授权和精确来源，保护现存及未提交内容，恢复后核对数量、内容、GUID与保护文件哈希。若只能恢复Git版本、无法找回删除前未提交值，单独登记限制。文件已由外部恢复时，只记录观测和验证，执行者未证就保持未知，不能倒填成本任务执行。

历史记录追加保留；更正说明旧结论如何被新证据替代，不能删除旧失败、拒绝或未知项。
