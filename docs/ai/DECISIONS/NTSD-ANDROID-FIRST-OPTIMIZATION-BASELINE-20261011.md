# Android 手机优先的优化基线

Decision ID：NTSD-ANDROID-FIRST-OPTIMIZATION-BASELINE-20261011  
状态：ADOPTED / DESIGN_PRIORITY_ONLY  
日期：2026-10-11

用户在当前讨论中明确：
> 应该先适配手机，先把性能压下来，这样转到PC时，只需要提高性能要求就行
> 比如重新压低要求更容易

## 已确定的方向

Android 手机是后续优化的首要设计约束。先在手机可承担的 CPU、内存、加载与上传开销下建立高效的共用实现，再让 PC 在这个基础上提高画质、分辨率、显示帧率和资源规格。这里“把性能压下来”按上下文指降低资源消耗和运行成本，不能解释为擅自减少实体、改变 AI 或降低既定战斗语义。

此前 Android 真机/GPU认证、构建和平台交付后置，只规定验证与交付顺序，不表示手机设计约束也后置。PC/Editor仍可用于源码、功能、像素等价、计数与受控成本验证；开发机的内存余量、核数、耗时和 Windows Private Bytes 不直接定义手机默认参数或通过标准。转到 PC 的主要方向是扩展表现档位及做平台验证，不能承诺不经验证即自动兼容。

## 预算和证据

- 手机预算应围绕具名设备档位和整局资源组成提出：稳定驻留、加载/切场峰值、解码/上传在途，以及其他系统预留。不能把标称 RAM 当作应用可用额度。
- 现有暂定 PC 配置及320MiB AudioClip、2GiB/3GiB进程指标保留原批准范围和历史证据，不用于认定 Android 达标，也不自动成为 M-12 手机预算。
- 手机具体机型/SoC/RAM、系统/图形API、分辨率/显示帧率与字节预算尚未冻结；不能自行填数或由这次方向决定推导已认证最低配置。
- 普通战斗与原千人压力/多资源最坏集合要各自记录。保留原实体规模、正式规则、精确33ms逻辑间隔及十一阶段关闭合同。原专项目标和暂缓状态不因本决定被修改。
- 本轮只同步方向和方案文档，没有运行 Android/Unity/Profiler/编译/测试/测量/构建，不能写成手机适配已完成。

## 下一项 M-12

沿用既有 M-12 解码上传字节背压方案，先补齐面向手机的预算分配建议及当前加载必要性，再决定准确实施范围与参数。不是先按开发机余量定默认，再在手机阶段重新压缩。

1. 区分解码中、处理完待上传、上传后仍供图集消费的像素；Color[] 与 Color32[]、旧新 publication 和纹理资源分别记录，汇总时避免共享对象双计。
2. 解码前按经校验尺寸申请异步字节额度；额度不足等待，保留既有 UniTask/后台解码/主线程上传路线。最大单资源、估算偏差、取消和失败策略须在具体方案中明确。
3. 待上传额度与仍被图集保留的像素分别管理；不能提前释放仍有消费者的数据，也不能让图集等待所有加载完成而加载又永久等待额度。字节额度归还不是进程内存已经即时下降的证明。
4. 用同指纹内容比较峰值与加载代价，并验证像素、裁切、UV、目录、共享身份及关闭/重入。若收益不足，具名结束候选；队列有界不等于全量驻留或整局峰值有界。
5. 先由主讨论会话形成有依据的手机档位/预算建议和取舍，不让用户凭空给出底层字节数字。实际代码修改照常以准确Task/Change登记，具体运行与设备证据据实区分。

## 既有结项与边界

H10 保持 CLOSED / USER_SCOPE_CLOSEOUT。已取消的 Windows Player Task/Change 保持 ABANDONED，第四 processor 待批问题保持撤回；不重开该路线。已有源代码和失败/限定证据不回退、不追溯改PASS。

H08已接入的共享默认ON、M03候选OFF、H07/producer暂缓、H06不续、95OFF及PERF/ATLAS/MONO/EXT-1等专项边界保持。手机优先不是自动启动所有平台、资源、Settings或架构专项；本次没有派发执行、启动下一任务/Goal或恢复自动监测。
