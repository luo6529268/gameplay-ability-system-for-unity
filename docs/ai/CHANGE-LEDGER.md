## 覆盖范围

下列自编写代码路径的修改必须有 Change Record：

- `Assets/NTSD/Scripts/` 下的 C#、shader/compute 或 editor/test 脚本；
- `Tools/` 下的自编写 PowerShell、Python、JavaScript、TypeScript、C# 或其他工具代码；
- 后续经用户批准纳入的本仓库自编写运行时代码。

文档、资源、场景、DAT 与项目设置本身不自动要求 Change Record；但只要它们与同一脚本行为改动共同交付，就必须列在该 Record 的“已改文件”中。第三方、生成代码和 build output 不得借本机制被私自修改。

## 状态口径

| 状态 | 含义 |
|---|---|
| `PLANNED` | 已创建记录，尚未改脚本。 |
| `IN_PROGRESS` | 正在实现，尚未完成代码写入。 |
| `CODE_WRITTEN` | 已写入代码，尚未取得编译证据。 |
| `COMPILE_PASS` | 相关编译或类型检查已实际通过。 |
| `FOCUSED_TEST_PASS` | 相关 focused test/self-check 已实际通过。 |
| `RUNTIME_PENDING` | 代码级证据具备，但仍缺 Play Mode/集成验收。 |
| `VERIFIED` | 已具备与风险相称的 authority、编译和运行时证据。 |
| `BLOCKED` | 明确记录阻塞原因和恢复条件。 |
| `ABANDONED` | 未继续实施，保留原因和工作树处理结果。 |
| `ROLLED_BACK` | 已回退，保留原失败证据和回退范围。 |
| `SUPERSEDED` | 被后续 Change ID 取代，必须链接替代记录。 |

`CODE_WRITTEN`、`COMPILE_PASS`、`FOCUSED_TEST_PASS` 和 `RUNTIME_PENDING` 都不是“已对齐”结论。对于 C++ release 行为，只有对应 Change Record 具备 C++ authority 链与相应验收，才能记录 `VERIFIED`。

## 激活基线

- 本账本激活前，工作树已存在用户/历史的文档、场景、资源 meta、项目设置和未跟踪目录改动；它们不自动归属给本账本。

## 使用顺序

1. 从 `TEMPLATES/CODE-CHANGE-RECORD.md` 新建 `CHANGE-RECORDS/<Change-ID>.md`，状态填 `PLANNED`。
2. 在本表新增一行，并将 Change ID 写入 `STATE.md` 的当前活跃改动项。
3. 记录 C++ authority 或用户明确需求、Unity 原状、目标文件/符号和验收合同。
4. 修改代码后更新 Record、Ledger、STATE 和 handoff。
5. 运行 `Tools/Validate-ChangeLedger.ps1`；含脚本的提交前再次运行。
