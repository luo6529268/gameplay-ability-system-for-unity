# H07-AI-MODE：独立千人模式中的密集区AI策略

父项H-07；状态DESIGN_PROPOSAL / USER_DECISION_REQUIRED。这是允许行为变化的模式候选，不称原规则等价优化；用户明确允许评估，不能仅因原版没有就否决。

## 可比较方案

A 决策分相：稳定实体身份（需含generation/出生规则）映射到K相位，每tick只决策一组。正常模拟仍33ms，物理/碰撞/生命周期/输入边沿仍每tick执行。是否保持上次意图或投影为按住/释放须明确；不能每次重复制造按下边沿。
B 拥挤疏散：用确定性局部密度和稳定tie-break选迁移目标，设置滞回避免来回改道；到达/路径受阻/目标失效要有明确状态转换。疏散会改变战斗动作与分布，减少碰撞成本只是待测假设。
C 迁区后攻击：显式移动/等待/可攻击状态，最大等待和可达性/拥堵策略由用户确认，不允许实体永久停止或静默跳过攻击。
先评估A；B/C不自动捆绑实施。感知/行发布仍可能每tick执行，不能把整个CharacterInput耗时当可按K倍缩减。

## 代码依赖与合同决策

现有SimulationAiDecisionModule/AiDecisionKernel、NTSD28InputTwoPassModule、profile解析和World reset/snapshot是核对入口。当前代码依赖未完整审计，不能直接增一个开关就实施。
需决定：适用模式/默认OFF、K和急迫事件响应、普通战斗保持原策略；新调度相位/意图/疏散状态的reset与保存恢复；RNG是否新分流及如何记录版本。
调度不能使用墙钟或非稳定遍历顺序。同seed+同模式+同输入应可重放；与旧模式checksum不同可以是批准的行为差异，但需要可识别模式/算法版本。先查现有回放配置是否已容纳标识，不预设必须改schema或新checksum命名空间。
不批准前不能取消现有原版比较断言；新模式的验收域需独立声明，不靠改旧测试变绿。

## 最小验证与完成

先从H07-INPUT成本解释可节省份额；通过具名设计决定选A/B/C，建立反应延迟、拥堵解除、公平性/饿死与目标失效场景。再运行模式内确定性、存取恢复、稳定slot复用、实际tick成本/容量/0GC/关闭及人工可玩性。
完成必须同时有性能收益和用户接受的新行为；模式通过不关闭原模式H07。无收益/可玩性差则保持默认OFF。模拟33ms/透明顺序/publication只读/11阶段关闭保持。
回滚只关闭新增模式入口及具名增量，不能改写旧回放原件；跨模式兼容政策须先批准。
