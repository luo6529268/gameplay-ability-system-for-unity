## 以后每份记录采用的格式

1. **优化点和要解决的问题**：写明父项、具体方法、复现条件、问题表现及定位证据。
2. **原来是什么代码**：保留改前真实片段及其来源；不能把 HEAD 当成含有用户未提交工作的改前版本。
3. **改成了什么代码**：列修改后对应片段，说明实际改动和没有引入的额外状态。
4. **为什么这样改**：用通俗说明连接代码变化与问题；把观察事实、测量结果、推断和未知分开。
5. **解决了什么**：列同条件前后结果、测量范围、可靠性校准和证据；没有测量的 CPU 收益不能补写数字。
6. **保持了哪些行为**：说明顺序、首匹配、异常、RNG/checksum、容量和生命周期中实际受影响的合同及验证。
7. **什么算本问题完成、还有什么没完成**：区分单点修复、候选准入、阶段性能和 Android 最终认证。补充未解决问题及下一步。
8. **证据与审计入口**：回链方案、唯一进度、Task、Change、报告和真实改前备份。

后续修改在原记录末尾追加日期、原因、代码/配置变化、验证和结论；历史结果保留其原来的范围。若实际结论发生变化，在文首说明更正，不把旧失败删除或改写成通过。未实施的优化点继续写在原有方案中，实施时再建立这份代码对照记录。
