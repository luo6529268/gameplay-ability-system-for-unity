### Verification result

`BattleRuntimeSelfCheck` covers:

- Generic Dvx throw: writes the current tick.
- Generic Kind-3 release: writes the current tick.

- Typed formal throw, Kind-3, consume, damaged drop, and character drop.

The fresh full self-check passed. Therefore LP-01 **ReleaseTick writer/reset behavior is self-check verified**. It remains **not Play Mode verified**.

### Residual link-contract note

The ReleaseTick conclusion must not be expanded to "all release link fields are equivalent" without a separate review. The authority formal helper (`WeaponRuntime.cs:289-295`) clears `LinkState` and the holder slot guard, but does not directly clear `holder.TargetIdx` or `held.HolderIdx`. Unity release helpers clear `TargetSlotIndex`/`HeldWeaponStableId` and set `HolderStableId = -1`. Existing Unity self-checks currently assert the latter values. This is a separately trackable link-field parity risk, not a failure of the ReleaseTick assertions.
