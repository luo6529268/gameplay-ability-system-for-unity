Implemented contract
--------------------
- Public three-state AiSensingMode. Legacy is enum/default zero. Shadow is opt-in.
  SoAAiSensing throws NotSupportedException and is also checked before ResetRuntimeState
  mutates state and before character-input passes begin.
- One preallocated scalar SoA column set per runtime slot. The row storage contains no
  LF2Entity, UnityEngine.Object, GameObject, Transform, List, or Dictionary references.
- BuildAiInputSlotSnapshot captures scalar data with occupancy epoch, handle generation,
  and runtime StableId identity. Any drift invalidates the shadow for the rest of the pass.
- A pure ascending brute scan reproduces initial nearest/bestDist/sameZLane, local-copy RNG
  cached selection, and post-special selection/flags. It does not write input or consume the
  world RNG. No second quadtree was introduced.
- Canonical PrepareAiInputBasic still executes exactly once and remains the only input/RNG
  authority. Its existing locals are compared against the pending shadow trace.
- Pending traces are paired by tick, runtime slot, generation, and StableId. Mismatches are
  buffered in a fixed bitmask and published only after a complete valid comparison. Invalid
  traces publish no result and increment no mismatch counter.
- CharacterInputAll and AiInputAndComboAll refresh the scalar row after each actually
  processed current-character-DAT entity's legacy handling without an LF2Character CLR
  check, covering human/AI/transformed shells and earlier-slot mutation visibility.
- Diagnostics expose fixed counters, cumulative/last mismatch masks, publish state, and the
  first structured mismatch. No tick-path strings, logging, boxing, LINQ, or collections.
- All five internal self-check entry points reject `_ticking` before changing state. Their
  temporary Shadow mode and snapshot build are exception-safe: previous mode is restored
  even when Build throws, and snapshot clear runs only after Build completed successfully.
- Normal pass snapshot clear preserves the last published comparison/mismatch diagnostics;
  new snapshot/query start resets stale published state, while invalidation still clears it.
