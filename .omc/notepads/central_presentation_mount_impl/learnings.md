# Learnings

- `LF2Character` obtains its runtime handle in `SimulationWorld.Register` after `OnAdded`; normal characters call `SetLogicObject` before that, so the registry refresh belongs at successful world registration rather than a presentation-frame poll.
- `EntityModel` and `Shadow` are siblings under the pooled entity root. Shadow ownership validation uses their shared direct parent and does not depend on GameObject names.
- Slot release can fail without changing the runtime claim. Presentation bindings are cleared before every release attempt and rebound from the retained handle only when that failure occurs.
- `SimulationWorld.Register` first unbinds `entity.ItrRest`, so a normally foreign-bound tracker cannot drive the later bind failure. To exercise registration rollback without altering production semantics, a self-check-only entity exposes an unbound tracker for that initial access, then exposes one foreign-bound tracker for cooldown reset, world bind failure, and rollback cleanup.
- `BattleRuntimeSelfCheck` invokes production prefab instantiate/activation from an Edit Mode static entry. `BattleCentralPresentationMount` must opt into editor lifecycle callbacks with `[ExecuteAlways]`; its lifecycle methods must ignore prefab-asset objects whose scenes are invalid so the cross-prefab Shadow owner remains unset on the source asset.
- Rendererless production checks must not infer sprite visibility from `SpriteRenderer`. For clone visibility, preserve renderer registration timing but validate `LF2Sprite.EntityVisible`, a non-hidden current pic matching `GetRenderPicIndex()`, identity with the resolved production catalog entry, and that entry's shared texture.
- `BattleDynamicMeshBackend.BattleMeshChunk.Upload` must replace all live submesh descriptors atomically with `Mesh.SetSubMeshes`; growing `subMeshCount` before individual `SetSubMesh` calls can transiently overlap the previous descriptor set on Unity 2022.3. Retain the empty-frame inert descriptor path so the preallocated index buffer survives reuse.
- P4's pool-overflow regression deliberately prewarms ten inactive `LF2ObjectPool` objects then spawns twelve opoint weapons. Slot 62 is the first overflow allocation, so a per-condition diagnostic there isolates the dynamically-created object path from the ordinary reused-prefab path.
- P8-C editor acceptance must reach runtime internals through narrow read-only `ForAcceptance`/`ForDiagnostics` APIs because the harness is compiled into the editor assembly. Production evidence remains fail-closed outside Play Mode; synthetic fixture evidence is labelled separately in the report.
