# NTSD 联机帧同步改造执行文档（可直接按清单落地）

> 目标：在现有 NTSD 架构上，落地“王者荣耀风格”的帧同步联机（房主/主机推进 + 输入预测 + 输入延迟）
> 当前结论：不需要推翻重做，重点补网络层与确定性保障。

---

## 0. 现状结论（先确认）

### 已具备（保留）
- `SimulationTickDriver`：固定 Tick 驱动（30Hz）
- `SimulationWorld`：`SimOrder + StableId` 确定性执行
- `SimInputBuffer`：按 tick 对齐输入
- `PhysicsState + SceneQuery`：自定义逻辑与碰撞（非 Unity 物理权威）

### 必须补齐
1. 确定性随机源（替换 `UnityEngine.Random`）
2. 网络房间与输入广播（Photon Fusion）
3. 输入延迟窗口（InputDelay）
4. 输入缺失时预测策略（不等待慢玩家）
5. 联机 StableId 分配规则
6. 一致性校验（hash）
7. **输入确认机制**（ET8 关键措施）
8. **输入重传机制**（ET8 关键措施）
9. **帧号对齐检查**（ET8 关键措施）

---

## 1. 总体实施顺序（建议按阶段执行）

- **Phase A（必须）**：确定性修复与验证
- **Phase B（必须）**：Fusion 房间 + 输入同步跑通
- **Phase C（建议）**：预测/延迟/超时策略完善
- **Phase D（建议）**：hash 校验与问题定位工具
- **Phase E（可选）**：快照回滚/断线重连

---

## 2. Phase A：确定性修复与验证（先做）

## A1. 替换随机数（Critical）

### 目标
将战斗权威逻辑中的 `UnityEngine.Random` 替换为统一 deterministic RNG。

### 已发现位置
- `Scripts/Animation/LF2Objects/LF2Character.cs`
  - 985
  - 1013
  - 1320

### 执行项
- [ ] 新增 `DeterministicRng`（固定 seed）
- [ ] 在 `SimContext` 或 `SimulationWorld` 中持有 RNG
- [ ] 将以上 3 处随机调用替换为 context.Rng
- [ ] 战斗逻辑中禁止新增 `UnityEngine.Random`

### 验收
- [ ] 同 seed、同输入序列，结果完全一致

---

## A2. 录制回放一致性测试

### 目标
证明“同输入序列 -> 同帧结果”。

### 执行项
- [ ] 新增输入录制器（记录 tick + input）
- [ ] 新增回放器（按 tick 注入 `SimInputBuffer.EnqueueForTick`）
- [ ] 新增 `WorldStateHasher`（每帧或每 N 帧计算 hash）
- [ ] 同一录制回放 10 次，比较 hash 轨迹

### 验收
- [ ] 10 次回放 hash 完全一致

> 若不一致：先停联机开发，继续排查非确定性来源。

## B2. 输入同步接入

### 目标
Fusion 负责房间网络传输；NTSD 继续负责战斗模拟。

### 执行项
- [ ] 定义 `NetworkInputData`（包含 FuncKeyMask 等）
- [ ] 在 Fusion 回调中采集本地输入
- [ ] **实现输入确认机制**（ET8 关键）
  - [ ] 记录每个玩家的输入到达状态
  - [ ] 只有所有玩家输入都到达才推进该帧
  - [ ] 超时后使用预测输入继续推进
- [ ] 将网络输入按 tick 注入 `SimInputBuffer.EnqueueForTick(...)`
- [ ] 驱动 `SimulationWorld` 在统一 tick 下推进

### 验收
- [ ] 2 人对战：移动/攻击均可同步
- [ ] 双端结果一致，无明显漂移

---

## B3. 联机 StableId 规则（High）

### 目标
联机时稳定执行顺序必须一致。

### 执行项
- [ ] 单机：可继续本地自增分配
- [ ] 联机：由 Host/权威端分配 StableId 并广播
- [ ] 客户端只消费，不自行分配
- [ ] **实现输入合法性校验**（ET8 关键）
  - [ ] 服务器校验输入是否在合理范围内
  - [ ] 检查输入频率是否异常
  - [ ] 拒绝非法输入并记录日志

### 验收
- [ ] 多端对象顺序一致（SimOrder 内 StableId 一致）
- [ ] 非法输入被拒绝

---

## 4. Phase C：王者式体验关键（不等慢玩家）

## C1. 输入延迟窗口（Input Delay）

### 目标
吸收网络抖动，减少“等输入”卡顿。

### 执行项
- [ ] 设定 `InputDelayTicks`（建议初始 4~6 帧）
- [ ] tick rate 固定 30（与 NTSD 同步）
- [ ] 压测不同 delay 值（2/4/6/8）
- [ ] **实现网络质量监控**（ET8 关键）
  - [ ] 实时监控 Ping/丢包率/抖动
  - [ ] 根据网络质量动态调整 InputDelay
  - [ ] 提供网络质量 UI 显示

### 验收
- [ ] 常见网络波动下不出现全局暂停
- [ ] InputDelay 能根据网络质量自动调整

---

## C2. 输入缺失预测

### 目标
某玩家输入迟到时，系统继续推进，不阻塞全局。

### 预测策略（按优先级）
1. 重复上一帧输入（推荐起步）
2. 空输入（最保守）
3. 自定义行为预测（后续优化）

### 执行项
- [ ] 输入缺失 fallback 逻辑
- [ ] 记录每个玩家连续预测帧数
- [ ] 超时阈值（如连续 90 帧）触发断线/踢出
- [ ] **实现输入重传机制**（ET8 关键）
  - [ ] 客户端记录最近 N 帧的输入
  - [ ] 定期检查服务器是否收到
  - [ ] 未收到则重传
- [ ] **实现追帧机制**（ET8 关键）
  - [ ] 检测客户端是否落后服务器
  - [ ] 落后超过阈值时加速推进（一次推进 2-3 帧）
  - [ ] 追上后恢复正常速度

### 验收
- [ ] 单个高延迟玩家不会拖慢所有人
- [ ] 慢玩家仅表现为停顿/抖动/追帧
- [ ] 网络丢包时输入能自动重传
- [ ] 掉线重连后能快速追上进度

---

## 5. Phase D：一致性监控（建议）

## D1. Hash 上报与比对

### 目标
快速发现“隐性不同步”。

### 执行项
- [ ] 每 30 帧（1 秒）计算一次状态 hash
- [ ] 客户端上报（或主机广播对比）
- [ ] 出现 mismatch 时打日志（tick、对象关键字段）

### 验收
- [ ] 对战过程中 hash 持续一致
- [ ] 异常时能定位具体 tick 与对象

## 6. Phase E：中长期（可选）

## E1. 快照/回滚
- 目标：迟到输入到达后可重演修正
- 成本：较大（需要核心状态完整序列化）
- **实现快照压缩**（ET8 关键）
  - [ ] 使用增量压缩（只保存变化的数据）
  - [ ] 压缩算法（GZip/LZ4）
  - [ ] 减少断线重连时的快照大小

## E2. 断线重连
- 目标：中途掉线后可恢复战局
- 方式：快照 + 若干帧输入补齐
- **实现快速追帧**（ET8 关键）
  - [ ] 重连后从最近快照恢复
  - [ ] 加速重演缺失的帧（一次推进多帧）
  - [ ] 追上后恢复正常速度

---

## 7. 对现有项目改动规模评估

### 小改动
- Fusion 房间与网络输入模块（新增为主）
- InputDelay/预测策略（外围机制）

### 中改动
- StableId 联机分配规则
- 输入来源收敛（只从 SimInputBuffer 进入权威逻辑）

### 大改动（可后置）
- 快照/回滚
- 若未来要求极端跨平台一致性：float -> fixed point

**结论**：
- 当前项目无需推翻重做。
- 先做 A+B+C 即可达到可联机可玩的帧同步版本。
