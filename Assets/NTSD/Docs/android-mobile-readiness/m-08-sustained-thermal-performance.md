# M-08 Android 持续负载与热降频验收方案

## 问题与边界

短时间性能通过不能排除手机温升、频率下降和系统调度变化。当前没有 10～20 分钟 Combat1000 的持续证据。本项不预设具体设备温度阈值，重点是性能随时间是否仍满足预算。

## 解决方案

1. 固定设备状态、环境、亮度、分辨率、FPS、网络和充电条件，记录测试前电量与温度。
2. 连续运行 Combat1000 至少 10 分钟，推荐 20 分钟；按 0～60 秒、5、10、20 分钟窗口统计。
3. 同时记录 logic/main/render/GPU、dropped tick、backlog、温度、电源/热状态和可获取的频率信息。
4. 冷机与热稳态证书分别保存，禁止用首分钟平均值代表持续表现。

## 验收条件

- 热稳态窗口 logic P95 仍 `<33 ms`，P99 不形成持续 backlog。
- 正常战斗 dropped tick 为 0，GC collection 与 capacity reject 为 0。
- GPU 和 visible frame 不出现持续性阶跃退化；若有降级策略，触发条件与画面影响已认证。
- 测试可由相同 APK、设备与条件重复。

## 测试条件

| 阶段 | 条件 | 记录 |
|---|---|---|
| 基线 | 静置后开始 | 初始温度、电量、环境、设备状态 |
| 冷机窗口 | 0～60 秒 | 全性能分位数与首帧 |
| 中段 | 5 分钟 | 温度、频率、backlog、GPU |
| 热稳态 | 10～20 分钟 | 性能门与降频趋势 |
| 恢复 | 停止负载后 | 资源释放、温度与内存恢复 |
