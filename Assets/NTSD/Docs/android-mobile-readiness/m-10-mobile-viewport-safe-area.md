# M-10 移动端取景、底部黑区与 Safe Area 方案

> 优先级：中  
> 状态：`OPEN / DEVICE_MATRIX_PENDING / WAITING_USER_APPROVAL`
> 最后更新：2026-10-06
> 本轮共同合同与启动门：[2026-10-06复核](../battle-optimization-rebaseline-and-start-gates-20261006.md)；本轮未运行本项测试/测量，实施待用户批准。
> 主登记表：[Android 移动端就绪度与 1000 AI 风险清单](../android-mobile-readiness-priority-risk-register.md)

## 问题与边界

用户已确认保留移动端底部黑区和平台取景，但刘海、挖孔、圆角、手势区、超宽屏、平板和旋转矩阵尚未认证。取景和触控布局可以适配屏幕，不能反写逻辑世界坐标。

## 解决方案

1. 定义统一 `MobileViewportContract`：设计分辨率、战斗 viewport、底部黑区、Safe Area、缩放/裁切、触控可用区。
2. Camera/平台表现只从合同派生，固定世界相机和逻辑边界保持用户批准语义。
3. H-03 触控 UI 使用同一 Safe Area 结果，方向和动作区不进入系统手势危险区。
4. 明确产品旋转策略；若允许旋转，重排期间暂停采集并清空输入边沿。

## 验收条件

- 16:9、19.5:9、20:9、平板和 cutout 设备上关键战斗区、底部黑区和平台取景符合合同。
- 触控按钮可达、不被遮挡、不与系统手势区冲突。
- 分辨率和方向变化不改变逻辑位置、碰撞、checksum 或固定世界相机规则。
- 截图和参数报告可以复现每种布局。

## 测试条件

| 测试 | 设备/模拟尺寸 | 通过标准 |
|---|---|---|
| 宽高比 | 16:9、19.5:9、20:9 | 取景与黑区符合合同 |
| Cutout | 刘海/挖孔/圆角 | 关键 UI 与角色不被非预期遮挡 |
| 平板 | 常见平板比例 | 不异常拉伸，触控可达 |
| 旋转 | 支持时左右横屏切换 | 布局重建、输入安全释放 |
| 逻辑不变 | 同 seed/input 不同屏幕 | checksum 一致 |

- 保存每个尺寸的 safe area、viewport 参数、截图、触控覆盖和 checksum 对照。
